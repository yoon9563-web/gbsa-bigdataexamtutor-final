# 요약노트 운영

## 수집

- 매 정답(독립·힌트 후 정답, 진단 포함)마다 채점과 진도를 보여준 다음 **“방금 푼 문제의 개념을 요약노트에 정리해드릴까요?”**라고 묻는다. 문제 ID와 개념을 미응답 제안으로 먼저 저장하고 이 질문이 있는 응답에는 다음 문제를 내지 않는다.
- 긍정 답변은 해당 개념·코드·문항 ID를 저장하고, 거절은 해당 제안만 닫는다. 답 없이 다음 문제를 요청하면 수업을 이어간다. 제안을 여러 개 보류한 상태에서 대상이 모호하면 어느 문제인지 확인한다. 언제든 “이건 마지막에 정리해줘” 같은 요청은 명시적 추가로 취급한다.
- 오답·힌트·해설을 통해 확인된 개념, 오답 원인과 필요한 코드 패턴을 기록한다. 학습자가 중단하거나 미채점인 시도는 확인된 오답으로 세지 않는다. 자주 틀린 개념은 서로 다른 문항에서의 오답 수로 우선순위를 매기고, 힌트가 필요했던 개념도 포함한다. 동일 문항의 재제출이나 메시지 재전송은 문항 수를 늘리지 않는다.
- 기록은 유형과 개념을 기준으로 합치되 대표 코드, 오류 원인, 출처 문항 ID와 사용자 요청 여부를 보존한다. 진행 중인 문제의 정답 코드는 그 문제의 힌트 규칙을 지킨다. 요약노트를 중간에 요청하면 진행 중인 문제와 다른 데이터로 예시를 작성한다.

## 발행 시점

- 요청하는 즉시 현재까지의 기록을 사용해 PDF를 만들어 전달한다. 학습자 기록이 없어도 공통 범위로 만들 수 있다.
- 수험생이 설정한 마지막 공부일에 마지막 배정 문항을 처리하거나 수험생이 그날 공부를 마치면 자동으로 발행한다. 마지막 날을 놓쳤거나 발행에 실패했으면 다음 접속에서 발행을 재시도한다. 대화형 자동화이므로 접속이 없는 동안에는 실행되지 않는다.
- 수동 요청은 언제든 최신 내용으로 다시 발행한다. 마지막 날 자동 발행은 성공 기록이 있을 때 중복 실행을 피한다. 여러 상황이 같은 턴에 겹치면 PDF 하나로 처리한다.

## PDF 본문 구성

### 유형 1 — 개인별 오답·약점

1유형의 풀이 기록이 있으면 오답·힌트·해설이 필요했던 코드와 정리 요청 항목을 우선한다. 각 항목은 문제에서 보이는 표현 → 사용할 코드 → 오류 원인 → 출력·경계 점검 순이다. 1유형 풀이 근거가 전혀 없으면 [데이터마님 120문항 색인](type1-index.md)의 모든 행을 훑고, 중복 코드 패턴을 하나로 묶어 모두 수록한다. 각 패턴 옆에 연결된 색인 번호를 적고 1~120번에 미매핑 번호가 없는지 검증한다. 색인만으로 세부 조건을 알 수 없으면 자체 가상 데이터로 예제를 만든다.

### 유형 2 — 이진분류·다중분류·회귀

개인 기록과 무관하게 세 가지 전체 풀이 흐름을 각각 싣는다. 파일 읽기 및 타깃·ID 확인 → 훈련/검증 분리 → 결측·범주 처리와 파이프라인 → 모델 학습 → 검증 지표 계산 → 전체 학습 재적합 → 테스트 예측 → CSV 저장·다시 읽기 순으로 필수 Python 코드를 붙인다. 공통 전처리는 한 번 설명하고 유형별 차이를 분명히 표시한다.

- 이진분류는 Accuracy/F1의 라벨과 ROC-AUC의 양성 확률을 구분하고 `classes_`로 확률 열을 찾는다.
- 다중분류는 Accuracy/Macro F1의 라벨과 다중 ROC-AUC의 확률 행렬 및 클래스 순서를 구분한다. 문제의 다중 AUC 방식과 제출 열 순서를 확인한다.
- 회귀는 `predict`와 RMSE, RMSLE의 `log1p` 및 비음수 조건을 예시로 준다. 파일명, 열명, ID 포함 여부는 각 문제 지시를 우선한다. 모든 흐름에 테스트 원래 순서, 행 수, 결측, `index=False`를 확인하는 코드가 있어야 한다.

### 유형 3 — 자주 연습하는 통계 코드

개인 기록과 무관하게 1표본·독립(등분산/Welch)·대응 t검정, 카이제곱 독립성/적합도 검정, 일원분산분석, 상관, 선형·로지스틱 회귀를 정리한다. 각 항목에 문제에서 고르는 기준, 데이터 구조, 필요한 import와 실행 코드, 통계량·p값·계수 추출과 반올림 위치를 포함한다. 단측·양측과 유의수준을 문제에 맞추고, p값으로 귀무가설을 판단하는 문장을 붙인다. 출제 빈도 근거가 확인된 기법을 앞에 배치하고, 그 외는 시험 대비 예제로 표시한다.

## 파일 저장과 검증

- `learners/<학습ID>/notes/` 아래에 편집용 Markdown과 최종 PDF를 저장한다. 학습자 기록 없이 공통본을 요청하면 `notes/` 아래에 저장한다. 파일명은 `summary-notes-YYYY-MM-DD`로 하고 버전을 남겨야 하면 접미사를 붙인다. 한국어 제목·본문과 고정폭 코드에는 한글이 표시되는 글꼴을 사용한다.
- 환경에서 사용 가능한 PDF 생성 도구로 변환한다. 페이지 길이에 맞춰 코드가 잘리거나 긴 줄이 넘치지 않게 구성한다. PDF가 열리고 한글·코드·세 유형의 필수 범위가 표시되는지 확인한 뒤 링크를 제공한다. 사용자가 다운로드할 수 있는 경로로 전달한다.
- PDF 생성이나 검증에 실패하면 Markdown을 유지하고 실패 사유를 알린다. 성공한 경우에만 학습 상태에 발행 시각, 생성 경로 및 마지막 날 자동 발행 여부를 기록한다.

## 학습 상태

기존 state.json에 summary_notes가 없으면 초기화한다. pending_offers, entries, exports를 각각 빈 배열로 두고 제안 문항 ID, 개념별 학습 근거, 발행 결과를 누적한다.
